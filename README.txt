# おえかきバトル

公開URL
https://art-battle-app.vercel.app/

概要
友だちと同じルームに集まり、制限時間内にお題の絵を描いて競う、モバイル対応のお絵描きパーティーゲームです。ルーム作成者が採点方法、描画時間、ラウンド数を決め、最大8人で対戦できます。採点はAI採点と参加者投票の2方式から選べるため、OpenAI APIキーがない環境でも遊べます。

開発背景
短時間で盛り上がれる「ゲームらしい共同体験」を題材に、フロントエンド、リアルタイム通信、サーバーAPI、外部AIサービスを一つのアプリケーションとして設計・実装しました。

単なるお絵描きアプリではなく、ルーム参加、同期タイマー、提出の競合制御、採点、順位・得点計算、再戦までを一連のゲーム体験として成立させることを目標にしています。AI採点には費用がかかるため、参加者だけで完結できる投票モードを併設しました。

主な機能
・5桁のルームIDでのルーム作成・参加（1〜8人）
・ニックネームのみで参加できる待機室
・採点方式の選択
  - AI採点: 作品画像をOpenAI Responses APIへ送り、0〜100点と短評を取得
  - みんなで投票: 自分以外の作品へ1票、または棄権を選択。AI APIを利用しない
・描画時間の選択（10 / 30 / 90 / 180秒）
・ラウンド数の選択（1 / 3 / 5 / 10ラウンド）
・40種類の日本語・一単語お題から、重複しないランダム出題
・HTML Canvasによるペン、色、太さ、消しゴム、全消去
・描画途中の線をSupabase Realtimeで共有するライブプレビュー
・端末間で共通の開始時刻・終了時刻を使う同期タイマー
・全員提出またはタイマー終了を契機に、採点・投票画面へ遷移
・順位ポイント（1位: 5点、2位: 3点、3位: 1点）と最終ランキング
・同一メンバーでのお題を変えた再戦、ホストによるルーム終了

技術スタック
・フロントエンド: Next.js 16 / React 19 / TypeScript
・描画: HTML Canvas API
・リアルタイム通信: Supabase Realtime（Broadcast）
・データベース: Supabase PostgreSQL
・AI採点: OpenAI Responses API（画像入力、JSON Schema形式の出力）
・スタイリング: CSS（ポップなパーティーゲーム調の独自UI）
・テスト: Vitest
・パッケージ管理: pnpm
・ホスティング・サーバーレスAPI: Vercel

システム構成

  [ブラウザ: Next.js / React]
       |  ルーム状態の取得・保存、提出、採点リクエスト
       v
  [Vercel Serverless API]
       |-- /api/game ----------- [Supabase PostgreSQL: rooms]
       |-- /api/game/submit ---- [Supabase PostgreSQL: rooms]
       |-- /api/judge ---------- [OpenAI Responses API]
       |
       +-- 環境変数でサービスロールキー・OpenAI APIキーを管理

  [ブラウザ]
       |  描画イベント（線分・消去）を配信
       v
  [Supabase Realtime Broadcast]
       |
       +-- 同じルームの参加者へライブプレビューとして配信

設計・実装上の工夫
・AIを使わない選択肢
  AI採点だけに依存せず、投票モードを設けました。API料金やキー設定を気にせず遊べるだけでなく、友だち同士の遊び方に合わせられる設計です。

・描画データを二層に分離
  描画中は完成画像全体を何度も保存せず、線分・消去といった小さなイベントだけをRealtimeで配信します。DBへ保存するのは提出時の圧縮JPEG画像だけにし、通信量と保存量を抑えています。

・端末間でずれないタイマー
  残り秒数を各端末で個別に減らすのではなく、サーバー状態に開始・終了時刻を保存し、各端末がその時刻との差分から表示を計算します。画面遷移や再読み込み後も、ゲームの時間軸をそろえやすくしています。

・同時提出への対策
  提出専用APIで最新のルーム状態を取得し、同一プレイヤーの二重提出を拒否します。更新時は状態のバージョンを条件にして競合を検出し、最大4回の再試行で同時提出による作品消失を防いでいます。

・状態遷移とポイント計算を共通化
  lobby / drawing / voting / results / finished のフェーズを明確に持たせ、順位計算・同順位・ポイント付与を共通ロジックに集約しました。ラウンド数が1、3、5、10でも同じルールで最終結果を判定できます。

・安全なキー管理
  OpenAI APIキーとSupabaseのサービスロールキーはVercelのサーバー環境変数にのみ保持し、ブラウザへ渡しません。Realtime接続には公開可能なSupabase URLと匿名キーだけを使用します。

苦労した点と解決
・提出直後に画面が進まない、作品が結果に出ない問題
  汎用的なルーム更新と大きな画像データの送信が競合しやすい点が課題でした。提出を専用APIに分離し、画像を圧縮し、競合検出とリトライを導入して安定性を改善しました。

・端末ごとにタイマーが異なる問題
  ローカルのカウントダウン開始タイミングに依存していたため、開始・終了時刻をルーム状態で共有する方式に変更しました。開始直後には短い共通カウントダウンを設け、参加者が同じタイミングで描き始められるようにしています。

・リアルタイム性と負荷の両立
  描画中のライブ表示はRealtimeを使い、ルーム状態の同期は変更があった場合だけデータを返す軽量なポーリングを組み合わせました。頻繁に変わる描画データと、確実に保存したいゲーム状態の役割を分けています。
